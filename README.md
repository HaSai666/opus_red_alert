# MECHA // ROGUE

第三人称机甲射击 + 肉鸽。浏览器运行,无需构建,无需安装。

> 仓库名沿用创建时的 `opus_red_alert`,但项目主题已改为机甲射击(见设计文档)。

## 运行

因为使用 ES Module 与 WASM,`file://` 协议下无法运行,需要一个静态服务器:

```bash
python -m http.server 8080
# 然后打开 http://127.0.0.1:8080/
```

或者直接用在线版本(GitHub Pages)。

## 调参面板(F1)

这是本项目最重要的一件工具。所有影响手感的数值都暴露为运行时滑杆——
相机距离与弹簧刚度、移动加速度、冲刺速度与冷却、射速与散布、热量与散热、
泛光与曝光。第三人称手感只能靠人眼判断,因此这些值不写死在代码里。

调好之后用面板底部的 **「复制参数 JSON」或「下载 config.json」** 导出,
再把内容给到开发者即可固化进 `src/config.js`。

面板里的「实时读数」还会显示 FPS、draw call、三角形数与当前分辨率比例,
并带三个调试开关:碰撞盒可视化、慢动作、顶部性能条。

## URL 诊断参数

排查渲染问题时非常有用:

| 参数 | 作用 |
|---|---|
| `?seed=7777` | 固定关卡种子。**不同种子生成不同房间与敌人站位**,对比截图前必须固定,否则两次画面没有可比性 |
| `?clean=1` | 隐藏全部 HUD,用于评估纯画面 |
| `?god=1` | 玩家免疫伤害,并压掉受击红闪。用于长时间观察场景而不被敌人打死 |
| `?nofog=1` | 关闭雾 |
| `?nopostfx=1` | 绕过 EffectComposer 直接渲染场景,用于区分「场景没画出来」与「后处理抹掉了」 |

## 架构

```
src/
  config.js          全部可调数值(手感参数的唯一来源)
  input/             输入采集,归一化为语义动作
  physics/           Rapier 封装、关卡几何与碰撞体
  simulation/        游戏规则:机甲、敌人 AI、武器、遗物、房间流程
  render/            渲染:相机、模型、粒子、特效、后处理、主循环
  ui/                HUD 与界面
  diagnostics/       调参面板
vendor/              依赖源码(three.js 0.169 / Rapier 0.14),已入库
docs/specs/          设计文档
```

**核心约束:模拟与渲染彻底分离。** `simulation/` 不 import three,不触碰 DOM,
只通过抽象物理接口与外界交互——因此游戏逻辑可以独立测试,而渲染层只读快照、
绝不回写状态。详见 `docs/specs/` 里的设计文档。

## 技术栈

| 层 | 选型 |
|---|---|
| 渲染 | three.js 0.169(源码已入库到 `vendor/`) |
| 物理 | Rapier 3D 0.14(wasm 内嵌,无外部文件) |
| 后处理 | EffectComposer + UnrealBloom + SMAA + 自定义合成(暗角/色差/颗粒) |
| 调参 | lil-gui |

**不需要 npm install,不需要构建步骤。** 依赖以源码形式入库,通过 importmap 解析。
这样做的原因:本项目没有 Node 环境,且 CDN 在生产环境不可靠(社区共识是生产项目
应 vendor 依赖)。

## 已知限制

- 机甲与敌人模型是**程序化生成的图元拼装**,不是美术资产。设计文档原计划使用
  CC0 模型(Quaternius Space Kit),但开发环境无法下载外部资产。`src/render/models.js`
  的 `buildMech()` 保持了返回 `THREE.Group` 的接口,日后替换为 GLTF 加载即可。
- 音效尚未实现。
- 单区域 5 个房间,无永久解锁与存档(属设计文档中「切片之后的量叠加阶段」)。
