01概述

一款处在开发早期的第三人称机甲射击 + 肉鸽（Roguelike）游戏。玩家操控一台作战机甲，空投进入程序化生成的废弃空间站，逐房间清剿敌人、获取遗物强化，最终击败区域 Boss 撤离。

本设计的所有取舍都服务于两个目标，且两个目标之间存在明确优先级：

  1. 画面质感优先 — 视觉效果是这个项目的立项理由。凡是有利于画面的决策，优先于开发便利性。
  2. 工程上必须可由 AI 主导开发 — 开发者本人无 3D 美术能力，且协作方（Claude）无法直接看到运行画面。这决定了技术栈、资产策略和调试接口的形态。

为什么选这个题材组合

经过对四类候选方向的比较（太空舰船战斗、抽象几何、单场景沉浸空间、RTS），最终选定第三人称机甲射击，原因是它在「画面性价比」和「工程可行性」上同时占优：

候选方向画面上限资产成本AI 可独立开发度结论
太空舰船战斗高极低高可行，但玩法偏薄
抽象几何视觉高无高不像「游戏」
红警类 RTS低极高中画面性价比最差
第三人称机甲射击高低中高选定
核心洞察

机械体主角是本案的杠杆点。人形角色的成本大头是骨骼绑定、面部和动画混合过渡——而机甲的动作僵硬是「合理的」，腿部动画可以完全省略（悬浮/履带），硬表面几何体可由程序化生成，画面质感从粒子与后处理而非从模型精度来。这一步直接绕开了整个项目最贵、最依赖人工调参的部分。

02方案对比与决策

技术栈的选择不是围绕「哪个引擎最强」，而是围绕「谁能让我（AI）独立闭环」。三者的核心差异在于反馈循环的长短。

① Unreal Engine 5

画面上限第一
  • Nanite / Lumen 让摆素材即出电影感
  • Fab 每月免费资产永久授权、可商用
  • Quixel 1500+ 扫描资产铺环境
否决原因：编辑器 GUI 驱动，我无法自测运行结果；C++ 编译 15–60 秒；每次改动需要开发者截图往返。反馈循环以分钟至十分钟计，垂直切片的迭代成本不可接受。

② Godot 4

折中方案
  • MIT 授权，无版税无门槛
  • GDScript 无编译，迭代快于 UE5
  • 下载仅约 60MB
否决原因：3D 高端画面上限明显低于 UE5，做不出「质感」这个立项理由；同时它同样是编辑器 GUI 驱动，我盲写代码的劣势没有改善。两头不占优。

③ Three.js 浏览器栈

✓ 选定
  • 秒级热重载，我能自己跑起来验证
  • shader / 粒子 / 后处理全部由代码驱动
  • CC0 GLTF 资产可直接加载
  • 无需安装，浏览器即运行
接受的代价：单场景几何复杂度不如 Nanite 级。但本作画面主体是屏幕空间特效（辉光、体积光、能量武器、爆炸粒子），而非百万面三角场景，此限制不构成瓶颈。

03资产策略（零成本、全 CC0）

开发者无 3D 建模能力、不购买商业素材。全部资产来自 CC0 公共领域库——可商用、可修改、免署名。

已核实的坑

KayKit 的 Combat Mech（带完整动画的机甲角色包）是 $19.99 起，并非免费，且条款要求不得原样转售。本设计不使用该包。Quaternius 的 Space Kit 已自带带动画的机甲，覆盖了同样需求且完全免费。

许可警告

Poly Haven / Kenney / Quaternius / ambientCG 是全库 CC0。但 Freesound 与 OpenGameArt 是逐文件混合许可——部分为 CC-BY（需署名），部分为 CC-BY-SA（衍生作品必须沿用同许可，商业发行时是实质性约束）。本作若从这两处取音效，必须逐文件核对许可证并记录来源清单。

04架构：模拟与渲染彻底分离

这是全案最重要的工程约束。它存在的理由不是「架构好看」，而是我的可验证范围边界：游戏规则（伤害公式、敌人决策、房间拼接）是纯逻辑，我能写单元测试自证正确；渲染与手感只能靠人眼判断。两者混写，我就失去了唯一的自测手段。

红线

渲染层不得修改 simulation 状态。所有视觉表现——炮口闪光、机体过热发红、爆炸、屏幕震动——都是对快照的反应，而不是状态的来源。违反这条，我就无法通过测试验证任何游戏逻辑。

为什么手感参数必须做进游戏

第三人称镜头是最容易做歪的部分，而我看不到画面。因此所有手感相关的数值都不写死在代码里，而是暴露为运行时可调的滑杆：

  • 相机 —— 距离、高度偏移、弹簧刚度、阻尼、俯仰限位、鼠标灵敏度
  • 移动 —— 加速度、最大速度、摩擦、冲刺距离与冷却
  • 战斗 —— 射速、散布、后坐力、热量增量、过热恢复时长

调试面板导出一个 JSON，你调好手感后把参数发给我，我固化进配置。这条路径把「我看不到画面」这个最大劣势，转化为一个可操作的流程。

机甲专属的三个机制

这三条是本作区别于普通第三人称肉鸽射击的地方，也是「机甲感」的来源。每一项都同时服务于玩法与画面：

机制玩法作用画面表现（特效长在机制上）
热量管理 开火积热，过热则强制停机数秒。制造「多打两发还是保守」的持续决策，节奏感强于传统换弹 散热口蒸汽喷发、装甲由暗转红的热辉光、过热瞬间全屏色差 + 警报音 + 视野边缘红色脉冲
推进器冲刺 冷却式短距冲刺替代跳跃。方向由输入决定，是主要闪避手段，构成攻防节奏的核心 推进器尾焰拖尾、起步瞬间的地面冲击波环、冲刺残影、镜头 FOV 快速外扩再回弹
部位挂载 左右手武器 + 背部挂载（导弹巢 / 护盾发生器 / 僚机无人机）。不同组合改变战术定位 背部挂载改变机体轮廓剪影；护盾展开时可见六边形能量网格；无人机有自己的引擎光点

遗物系统

遗物按稀有度分三档。设计红线：每个遗物改变机制，而非增加百分比数值。这是肉鸽好不好玩的分水岭——「伤害 +5%」不产生任何决策，「冲刺会留下爆炸残影」会产生全新打法。

Common 普通
增压阀
热量阈值 +40%，但过热后停机时间翻倍。用风险换输出窗口。
Rare 稀有
爆震护盾
冲刺穿过敌人时造成伤害并击退。让位移本身成为武器，改造整个战斗节奏。
Legendary 传说
过载核心
过热不再是惩罚：停机期间释放一圈电磁脉冲，瘫痪周围敌人 3 秒。把负面状态变成主动技。

07第一个里程碑：垂直切片

不追关卡量，只验证「手感 + 画面」。范围刻意压到最小——如果这个切片手感对了，后续加房间、加敌人、加遗物都是纯粹的量叠加，风险极低。

#交付项验收标准
1工程骨架 + Vite/TS/Three 配置npm run dev 打开浏览器看到空场景，帧率稳定 60
2程序化房间拼接（Quaternius 模块化套件）一个封闭房间，含地板/墙/掩体，有光照与阴影
3机甲移动 + 推进器冲刺WASD 移动、鼠标转向、Shift 冲刺，带加速度与惯性
4第三人称相机弹簧臂跟随、镜头防穿墙、鼠标俯仰限位
5一把武器：射线检测 + 热量左键开火、命中判定正确、热量条累积、过热强制停机
6两种敌人：冲锋型 + 远程型会追击/会保持距离射击，有血条，可被击杀并有死亡爆炸
7遗物三选一界面清空房间后弹出、可选中、效果真实生效
8调试面板（手感滑杆）相机/移动/战斗参数全部可实时调整，可导出 JSON
不在本里程碑内

音效 · Boss · 永久解锁与存档 · 多种机体 · 多区域 · 主菜单 · 设置界面。这些都属于切片验证通过之后的量叠加阶段。

08风险与对策

风险影响对策
手感调参
高概率		 第三人称镜头最容易做歪，而 AI 看不到运行画面，可能反复来回 全部参数暴露为运行时滑杆 + 导出 JSON；提供「参数怎么调」的说明文档；每个参数附合理区间与默认值
性能
中概率		 肉鸽需同时刷大量敌人，粒子一多即掉帧；浏览器端无引擎级优化兜底 第一天就上对象池（子弹/敌人/粒子）与敌人 LOD；Bloom 等后处理保持「可关闭可度量」，不允许掩盖可玩性
范围膨胀
最高风险		 前期引擎调研中最硬的结论：独立项目极少死于引擎选错，几乎都死于范围失控 里程碑制。切片必须做到「可玩可停」——任何时刻停下，手上都是一个完整能玩的东西
CC0 资产风格不统一
中概率		 Quaternius 与 Kenney 的低模风格不同，混用会造成视觉割裂 确定统一的后处理链（色调映射 + 色彩分级 + Bloom 参数）作为「风格统一器」；材质统一走同一套 PBR 参数

09待决问题

  1. 项目目录命名 — 本文档暂用 E:\wk_github\mecha-roguelike，可改。
  2. 美术风格的最终锁定 — 低多边形风格化（当前方案）vs 尝试接近写实。写实需要更精细的材质与光照投入，且在 CC0 资产下较难达成一致。
  3. 是否为浏览器独占 — 当前为纯 Web。若日后想上 Steam，需要 Tauri/Electron 打包，架构上无阻碍但需早做决定以免影响输入处理方式。
